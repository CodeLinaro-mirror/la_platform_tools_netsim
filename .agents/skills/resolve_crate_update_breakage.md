# Resolving Build Breakages from Crate Updates

This guide describes how to resolve build breakages in Netsim caused by updates to external Rust crates in Android.

## Problem
An external Rust crate used by Netsim is updated in Android, causing Bazel build failures because the local `BUILD.bazel` file for that crate is out of sync with the new version's dependencies or features.

## Solution Pattern

1. **Identify the failing crate**:
   - Run the build (`tools/netsim/scripts/build_tools.py --task build`) to see the build error and identify which crate is failing.
   - Alternatively, use input from the user if they specified the failing crate.
   - Locate the corresponding `BUILD.bazel` file in `hardware/generic/goldfish/third_party/rust/crates/netsim_build/` or similar location.

2. **Check the updated crate in Android**:
   - Locate the crate's source directory in Android (e.g., `external/rust/android-crates-io/crates/<crate_name>/`).
   - Read the `Android.bp` file generated by `cargo_embargo` to see what dependencies and features are used for the Android build.
   - Read `Cargo.toml` to understand conditional dependencies and features. Note that you may need to recursively check the `Cargo.toml` of dependencies if the dependency graph is complex.

3. **Align Bazel BUILD file with Android.bp**:
   - Update the `rust_library` target in the `BUILD.bazel` file.
   - Match `rustlibs` from `Android.bp` to `deps` in Bazel (e.g., `liblibc` -> `@libc`).
   - Match `features` from `Android.bp` to `crate_features` in Bazel.
   - Remove any dependencies that are no longer needed in the new version.
   - Check `CHANGELOG.md` or commit history if dependencies were removed to confirm they are no longer needed.

4. **Run buildifier**:
   - Run `buildifier <path_to_BUILD.bazel>` to fix any formatting or lint issues.

5. **Verify**:
   - Run the Netsim build to verify the fix: `tools/netsim/scripts/build_tools.py --task build test`.

## Example: `which` crate update (v8.0.2)
When `which` crate was updated, it failed to build because it no longer depended on `rustix`, `home`, and `either`, and instead used `libc` with the `real-sys` feature.

**Original `which.BUILD.bazel`:**
```python
rust_library(
    name = "which",
    srcs = glob(["src/**/*.rs"]),
    crate_name = "which",
    edition = "2021",
    deps = [
        "@either",
        "@home",
    ] + select({
        "@bazel_tools//src/conditions:windows": ["@once_cell"],
        "//conditions:default": [
            "@rustix",
        ],
    }),
)
```

**Updated `which.BUILD.bazel`:**
```python
rust_library(
    name = "which",
    srcs = glob(["src/**/*.rs"]),
    crate_name = "which",
    edition = "2021",
    crate_features = ["real-sys"],
    deps = select({
        "@bazel_tools//src/conditions:windows": [],
        "//conditions:default": [
            "@libc",
        ],
    }),
)
```
